3分でわかる ModularPhaseNet

AIの「話の筋が通っているか」を、
整数の掛け算3回で確かめる。

ModularPhaseNet は、前作 QuantumPhaseNet の考え方を ふつうのGPU・CPUで動く整数計算に置き換えた枠組みです。 概念の上下関係、話の進む向き、文脈の矛盾——この3つを、 複素数も量子コンピュータも使わずに、厳密に計算できる形にします。

Kiyotaka Kasubuchi & Kazuo Fukiya ／ 2026年8月11日 ／ 理論編（実験はこれから）
SCROLL
01 // ISSUE

「もっともらしいが、筋が通っていない」を見つけたい

LLM の誤りには、単語レベルでは正しく見えるのに、文章全体としては両立しない種類のものがあります。 1文ずつ検査しても引っかからず、通しで読むと矛盾している——実務で最も厄介なのがこのタイプです。

🪜

上下関係が崩れる

「この部品は装置の一種です」と「この装置は部品の一種です」を、モデルが同じ強さで書いてしまう

🧭

話が横に逸れる

長い回答の途中で論旨が別方向へ移り、最後の段落が最初の問いに答えていない

🔁

多段でだけ矛盾する

A→B、B→C、C→A の各ステップは正しく見えるのに、3つを合わせると成立しない

3つ目が特に重要です。局所的な含意判定をいくら積み上げても、 「一周して戻ってきたときに辻褄が合うか」は見えません。 ModularPhaseNet は、この「一周」を数えられる形にすることを狙っています。

02 // IDEA

意味に「時計の目盛り」を与える

01
FINITE DIAL

連続の針を、目盛りのある文字盤に置き換える

前作では、言葉の意味に連続的な「位相（波の位置）」を持たせていました。 本作はこれを、たとえば256個の目盛りしかない文字盤の上に丸めます。 目盛りに落とすと、位相の足し算・引き算が誤差ゼロの整数演算になります。

連続の角度は足すたびに誤差が乗りますが、時計の目盛りなら「3時＋4時間＝7時」がいつでも正確。 同じ入力からは必ず同じ答えが再現されます。
02
NESTED ADDRESS

粗い目盛りが、そのまま上位概念になる

256目盛りの文字盤を128、64、32…と粗くしていくと、細かい概念がだんだん同じ区画にまとまります。 この「まとまり方」がそのまま概念の階層になります。 犬とオオカミは粗い目盛りでは同じ区画、細かい目盛りでは別の区画、という具合です。

郵便番号に似ています。上3桁で都道府県、下まで見れば町名。 桁を落とすほど広い括りになる、という関係が数学的に保証されています。
03
CLOSING THE LOOP

一周して元に戻るかで、矛盾を検出する

文と文のつながりごとに「ここでどれだけ意味が回転したか」を予測します。 A→B→C→A と一周したときに、回転量の合計がちょうど元に戻れば整合、ずれていれば矛盾。 判定は掛け算3回の整数計算で終わります。

測量の閉合誤差と同じ発想です。一周して元の杭に戻らなければ、どこかの測定が間違っている。 どの一歩が悪いかは分からなくても、「両立しない」ことは確実に分かります。

重要なのは、つながりの回転量を各辺ごとに独立に予測する点です。 もし各点の値の差から自動計算してしまうと、一周は必ずゼロになり、検査が意味を持ちません。 論文はこの落とし穴を明示して、独立予測を設計の必須条件としています。

03 // HOW

1つの文章が処理される流れ

1
位相を割り当てる
各トークンに、文字盤上の目盛り（群の要素）と「深さ」を割り当てる。既存モデルの上位2〜4層にアダプタを挿すだけで足りる
2
階層を読む
目盛りを粗くしていったときのまとまり方から、どちらが上位概念かを判定する
3
向きを測る
文と文のつながりごとに回転量を予測し、文章全体が進むべき方向とどれだけ揃っているかを見る
4
一周を検査する
三角形のループを選び、回転量の積が元に戻るかを整数演算で確認する
5
Attention に戻す
階層・向き・矛盾・根拠の4つを、実数の加点／減点として通常の Attention に足す。既存の実装を書き換える必要はない
6
危うさを校正する
4つの指標に「根拠の薄さ」と「意味の曖昧さ」を足してリスクを算出し、正解ラベル付きデータで確率に較正する。閾値を超えたら、答える／調べ直す／作り直す／黙るを選ぶ
04 // LINEAGE

3本の論文のどこに位置するか

WavePhaseNet
意味を周波数に分解し、低周波を全体の主題、高周波を局所的な表現として扱う。ハルシネーションが構造的に避けられない理由を定式化した
arXiv:2602.14419
QuantumPhaseNet
同じ着想を、複素ベクトル束・ゲージ接続として書き直した。連続的で表現力は高いが、複素演算と量子アルゴリズムを含む
arXiv:2608.15820
ModularPhaseNet
その位相チャネルだけを有限の目盛りに落とし、整数演算で厳密計算できるようにした。量子ハードウェア・複素行列積・離散対数計算はいずれも不要
2026.08.11 ／ arXiv:2609.06000

つまり本作は「軽くて動く版」です。ただし論文は、 離散化しても表現力が増えるわけではないことを明記しています。 得られるのは表現力ではなく、厳密さ・再現性・検査可能性です。

05 // STATUS

いまどこまで確かめられているか

⚠ 最初に断っておくこと
  • この論文は理論編であり、実験はまだ実施されていません。性能の実測値は一切報告されていません。
  • 前作 QuantumPhaseNet には試作検証がありましたが、本作にはありません。論文はこれを Abstract と投稿コメントの両方で先に宣言しています。
  • 代わりに、実験を始める前に評価計画・データセット・比較対象・反証条件を固定して公開しています（事前登録）。

PROVEN — 数学的に示されていること

  • 目盛りを細かくするほど、連続版とのずれが小さくなる（上界が明示されている）
  • 目盛りを粗くしたときのまとまりは、必ず入れ子になる（階層が壊れない）
  • 整合スコアは、座標の取り方を変えても値が変わらない
  • すべてのループで矛盾がなければ、全体として一貫した意味の割り当てが存在する
  • Attention の出力は発散しない（有界性）

NOT YET — これから検証すること

  • 実データで階層復元・矛盾検出・リスク校正が既存手法を上回るか
  • 「回転が小さい＝上位概念」という対応が本当に成り立つか
  • 目盛りの数をいくつにすれば精度とコストが釣り合うか
  • 改善が、単なるパラメータ増加や検索強化で説明できてしまわないか
06 // USE CASES

どんな業務に効きそうか

長い技術文書の整合チェック

仕様書・報告書の中で、離れた箇所どうしが矛盾していないかを、一周検査で機械的に洗い出す

→ 局所検査では見えない多段矛盾に効く

社内用語の階層整理

装置・部品・工程などの上下関係を、粗い目盛りから細かい目盛りへの分岐として保持する

→ 階層の一貫性が構造から保証される

RAG の回答ゲート

根拠の薄さと文脈の矛盾を合わせたリスクを較正し、閾値を超えたら再検索または「わかりません」を返す

→ 誤答より棄権が望ましい業務に適合

オンプレ・閉域での運用

整数演算とテーブル参照だけで推論が完結し、専用ハードウェアも外部APIも不要

→ 機微データを外に出せない環境向き

いずれもこれから検証する用途であり、現時点で実測に裏づけられた効果ではありません。 導入を検討する場合は、後述の順序で小さく試すことを想定しています。

07 // SCOPE

できること／できないこと

できること

  • 階層・方向・矛盾・根拠・不確実性を、同じモデルの中で数値として観測する
  • 同じ入力に対して必ず同じ判定を返す（再現性）
  • 既存 Transformer のカーネルを書き換えずに組み込む
  • 危ういときに答えを止める（棄権）判断の材料を出す

できないこと

  • ハルシネーションをゼロにすること。知識欠落・検索失敗・引用誤りは別問題として残る
  • 計算を速くすること。Attention の二次コストは解消されない
  • 不規則なオントロジー（多重継承）をそのまま表現すること
  • 量子計算の優位性を古典で再現すること（本作はそもそも量子を使わない）
08 // ADOPTION

試すなら、この順番で

1
小さい文字盤から始める
目盛り数は32か64程度から。いきなり256にしない。学習コストを抑えて挙動を見る
2
上位層だけにアダプタを挿す
事前学習済みモデルの本体は凍結し、アダプタのみ学習する。効果が見えてから範囲を広げる
3
一周検査を三角形に限定する
すべてのループを見ると計算が膨らむ。まず三角形と短い基本サイクルだけに絞る
4
校正データを分ける
リスク較正に使うデータと最終評価データは必ず分離する。ここを混ぜると数字が信用できなくなる
5
対照実験を先に決める
単純なカテゴリ符号、位相をシャッフルした対照、目盛り数を変えた比較。効果が本物かを切り分ける設計を先に置く
09 // FAQ

よくある質問

量子コンピュータは必要ですか。

不要です。前作 QuantumPhaseNet に含まれていた量子フーリエ変換・位相推定・振幅増幅は、本作ではすべて取り除かれています。動くのは通常の GPU・CPU です。

「冪剰余」を使う意味は何ですか。単なる番号でよいのでは。

表現力の観点では同等であり、論文もそれを認めています。冪剰余を使う理由は、合成が厳密であること、部分群への射影が同じ演算で書けること、チェックサムとして機能すること、そして再現性が保証されることです。比較のため、単純な剰余を使うベースラインが必ず実験に含まれます。

目盛りに丸めると情報が落ちませんか。

落ちます。ただし落ちる量の上限が数学的に示されており、目盛りを増やせば単調に小さくなります。どこで精度とコストが釣り合うかは、評価計画の RQ5 として検証対象になっています。

推論は遅くなりますか。

追加コストは発生します。ただし推論時の位相計算は事前計算したテーブルの参照で済むため、実装上の負荷は小さく設計されています。一方で、Attention 全体の計算量が減るわけではありません。速度改善は本作の主張ではありません。

既存の学習済みモデルに後付けできますか。

想定されている使い方がまさにそれです。上位2〜4層に位相アダプタを挿し、本体を凍結したまま学習を始める形が初期実装として示されています。

実験結果はいつ出ますか。

本稿には含まれていません。評価計画・データセット・比較対象・反証条件が先に固定されているため、実験が行われた際には、この計画に対する答え合わせとして読むことができます。
