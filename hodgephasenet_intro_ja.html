3分でわかる HodgePhaseNet

AIの中の「意味の流れ」を、
3つの成分に分けて見る。

HodgePhaseNet は、文と文、主張と主張のあいだを流れる「意味の向き」を、 一貫した向き・小さな回り込み・大きな一周の3つにきれいに分ける枠組みです。 分け方は数学的に一通りに決まり、その結果を AI の注意（Attention）の配分に戻します。 前3作で作ってきた道具は、この「流れ」を作るための材料として使われます。

Kiyotaka Kasubuchi & Kazuo Fukiya ／ 2026年9月 ／ 理論・設計編（実験はこれから）
SCROLL
01 // ISSUE

「どこがおかしいのか」まで知りたい

前作 ModularPhaseNet は、つながりを一周したときに辻褄が合うかを「合う／合わない」で判定しました。 ただ実務では、その次の問いが出てきます。ずれているのは全体の向きなのか、小さな三角関係なのか、大きな話の輪なのか。

➡️

全体の向き

「A は B の上位概念」「B は C の上位概念」のように、全体を1本の物差しで並べられる部分

🔺

小さな三角の回り込み

A→B→C→A の3者のあいだで、向きが一周してしまう部分。推移律の破れのこともあれば、正当な相互参照のこともある

⭕

大きな一周

どの小さな三角でも説明できないのに、長い話の輪をぐるりと回り続ける部分。裏付けのない循環論法のことも、意図した話題の回帰のこともある

この3つは混ざって観測されます。HodgePhaseNet は、混ざった流れを3つに一意に分けることを狙っています。 ただし、分けた結果のどれが「誤り」なのかは、分け方だけでは決まりません。それは実験で確かめる対象です。

02 // IDEA

川の流れを3つに分けるように

01
NODES, LINKS, FACES

意味のつながりを「網」として描く

文や主張を点、そのあいだの関係を矢印でつないだ網を作ります。 さらに「この3つの関係はひとまとまりで合成できる」と判断した三角形には膜を張ります。 どの三角形に膜を張るかは、明示したルールで決めます。

地図の上で、町を点、道を矢印、区画を面として描くイメージです。 区画として囲った場所と、囲っていない大きな周回路を区別できるようにしておきます。
02
ONE WAY TO SPLIT

流れを3つに分ける方法は、一通りしかない

矢印ごとの「流れの強さ」を、高さの差で説明できる部分（一貫した向き）、 膜を張った三角形の中の渦（小さな回り込み）、膜のない大きな輪を回る流れ（大きな一周）、の3つに分けます。 この分け方は互いに重ならず、一通りに決まることが数学的に保証されています（離散 Hodge 分解）。

水路の流れを、坂を下る流れ、小さな池の中の渦、湖を一周する流れに分けるようなものです。 全体のエネルギーは、3つのエネルギーのちょうど合計になります。
03
BACK TO ATTENTION

分けた結果を「どこに注目するか」に戻す

3つの成分の値を、AI が「どの語を参照するか」を決める注意の配分に、小さな加点・減点として足します。 加点の重みをゼロにすれば元のモデルと完全に同じに戻ります。 どの成分を加点・減点に使うかは、データから学習します。

地図に「ここは渦が強い」「ここは大きな周回路の一部」という注記を足して、読み手の目の配り方を少し変えるイメージです。 地図そのものは書き換えません。

重要な落とし穴が1つあります。各点の値の差だけで矢印の強さを作ると、 渦も一周も必ずゼロになり、分ける意味がなくなります。 論文はこれを証明したうえで、矢印ごとの関係を独立に評価する「関係エンコーダ」を必須にしています。

03 // HOW

1つの文章が処理される流れ

1
網を作る
隣り合う語、知識や根拠でつながる語、元の注意で強く結ばれた語のあいだに、上限付きで矢印を張る。ルールで認めた三角形にだけ膜を張る
2
矢印ごとの流れを評価する
関係エンコーダが各矢印の両方向を評価し、逆向きなら符号が反転する流れを作る。周波数・位相・有限群の特徴（前3作）や検索した根拠を材料にする
3
3つに分ける
疎な連立方程式を2つ解くだけで、一貫した向き・小さな回り込み・大きな一周が求まる
4
注意の配分に戻す
「どちら向きに見ているか」を考慮した特徴量から、語の組ごとの加点・減点を作り、通常の注意に足す
5
未来を覗かない
文章を生成するときは、その時点までに見えている部分だけで網を作る。後ろの語を使うと、マスクをしていても情報が漏れるため
6
危うさを校正する
成分の比率・前作の一周検査・根拠の支持・意味の曖昧さからリスクを算出し、別に用意した正解付きデータで確率に較正する
04 // LINEAGE

4本の論文のどこに位置するか

WavePhaseNet
意味を周波数に分解し、低周波を全体の主題、高周波を局所的な表現として扱う。本作ではスケールの特徴として使われる
arXiv:2602.14419
QuantumPhaseNet
位相を座標に依らない形で比べる規則（接続）を導入。本作では比べ方の特徴として使われる
arXiv:2608.15820
ModularPhaseNet
一周して元に戻るかを整数演算で厳密に検査。本作では整合性の特徴として使われる
arXiv:2609.06000
HodgePhaseNet
3作の特徴から作った「意味の流れ」を、一貫した向き・小さな回り込み・大きな一周に一意に分け、注意に戻す
2026.09 ／ arXiv:2610.14971

前3作が数学の舞台を入れ替えてきたのに対し、本作は3作の出力を受け止めて統合する場所を作った論文です。 ModularPhaseNet の一周検査が「合う／合わない」を答えるのに対し、本作は「ずれがどの種類の流れにあるか」を実数で配分します。 両者は置き換えではなく、並べて使うことが想定されています。

05 // STATUS

いまどこまで確かめられているか

⚠ 最初に断っておくこと
  • この論文は数学とアーキテクチャの提案で、自然言語での性能結果は報告されていません。
  • 前作 QuantumPhaseNet の合成データでの検証結果は、本作の証拠としては使われていません。
  • 「小さな回り込み＝矛盾」「大きな一周＝知識の欠落」とは言えないことを、論文自身が明記しています。

PROVEN — 数学的に示されていること

  • 流れを3つに分ける方法は一通りで、3つは互いに直交する
  • 全体が1本の物差しで並べられるのは、回り込みも一周もゼロのときに限る
  • 点の値の差だけで作った流れには、回り込みも一周もない
  • 矢印の向きの付け方を変えても、注意への加点・減点は変わらない
  • 前提を満たせば、座標の取り方（ゲージ）を変えても結果は変わらない
  • 5頂点の小さな例で、すべての数値がぴったり一致する

NOT YET — これから検証すること

  • 回り込み・一周の成分で、正当な循環と問題のある循環を見分けられるか
  • 同じコストの単純なモデルより、事実の誤りを減らせるか
  • リスクの見積もりが既存の不確実性指標より正確か
  • 膜の張り方を変えても結論が保たれるか
06 // USE CASES

どんな業務に効きそうか

長い文書の論旨診断

報告書・仕様書の主張どうしの関係を網にし、ずれが局所的な三角関係にあるのか、章をまたぐ大きな輪にあるのかを切り分ける

→ 「矛盾あり」の先の、どこを見直すべきかの手がかり

用語・概念の上下関係の点検

一貫した向きの成分で上下関係を並べ、並べきれない回り込みを候補として提示する

→ 階層の破れを候補として洗い出す

多段推論の監査

根拠から結論へのつながりに、どの根拠でも支えられない大きな循環が混ざっていないかを数値で見る

→ 循環論法の候補を可視化

RAG の回答ゲート

成分の比率・一周検査・根拠の支持を合わせたリスクを較正し、閾値を超えたら再検索や回答保留に回す

→ 誤答より保留が望ましい業務向き

いずれもこれから検証する用途であり、現時点で実測に裏づけられた効果ではありません。 特に「回り込み」や「一周」が見つかっても、それが誤りとは限らない点に注意が必要です。

07 // SCOPE

できること／できないこと

できること

  • 意味の流れを、向き・小さな回り込み・大きな一周に一意に分けて数値で観測する
  • 分けた結果を、元のモデルを壊さずに注意の配分へ戻す（重みゼロで元に戻る）
  • 前3作の特徴を1つの場所に集めて使う
  • 生成中でも、未来の語を使わずに計算する

できないこと

  • 回り込みや一周を、それだけで「誤り」と判定すること
  • 網の作り方（どの三角形に膜を張るか）に依存しない結論を出すこと
  • 計算を速くすること。生成時はむしろ計算が増えうる
  • 根拠そのものが間違っている場合を見抜くこと
08 // ADOPTION

試すなら、この順番で

1
合成データで分解を確かめる
答えの分かっている網で、3成分が正しく復元されるかを先に確認する。これは実装の検査で、言語での効果の証拠ではない
2
1つの層・1つのヘッドから
選んだ層とヘッドだけに入れ、加点の重みをゼロにすると元に戻ることをまず確認する
3
膜の張り方のルールを先に決める
どの三角形を面にするかで結果が変わる。評価用の正解を見ずに決められるルールを先に固定し、変えた場合も比べる
4
向き・ゲージ・未来漏れのテスト
矢印の向きをランダムに反転しても結果が変わらないこと、後ろの語を編集しても前の出力が変わらないことを自動テストにする
5
同じコストの対照と比べる
分解を使わない同じ規模の関係モデルや、より強い検証器と比べ、改善が分解によるものかを切り分ける
09 // FAQ

よくある質問

ModularPhaseNet の一周検査と何が違うのですか。

ModularPhaseNet は有限群の上で「一周して元に戻るか」を厳密に判定します。HodgePhaseNet は実数の流れを、一貫した向き・小さな回り込み・大きな一周にエネルギーとして配分します。前者は Yes/No の検査、後者は内訳の分析で、論文は両者を並べて評価することを勧めています。

「大きな一周」が見つかったら、知識が欠けているということですか。

そうとは限りません。意図して最初の話題に戻る構成でも一周は生じます。論文は「調和成分は自動的に知識の欠落を意味しない」と明記しており、意味づけは実験で確かめる対象です。

計算は重くなりますか。

重くなります。1回の分解は疎な連立方程式を解くだけですが、文章を生成しながら毎回「見えている部分だけ」で解き直すとコストが増えます。論文は速度の改善を主張しておらず、実時間とメモリの実測報告を求めています。

既存の学習済みモデルに後付けできますか。

設計上は可能です。注意の配分に加点・減点を足すだけで、重みをゼロにすれば元のモデルに厳密に戻ります。ただし関係エンコーダの学習は必要です。

前3作を読んでいないと使えませんか。

分解そのものは前3作に依存しません。前3作の特徴は関係エンコーダの任意の入力で、どの特徴が効くかもアブレーションで確かめる計画になっています。

実験結果はいつ出ますか。

本稿には含まれていません。次の一歩として、監査可能な参照実装による合成データでの復元、同条件のベースラインとの比較、独立にラベル付けした正当・不当なサイクルでの評価が挙げられています。
